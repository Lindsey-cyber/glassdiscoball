# 果蝇罗盘：从连接组到环 · 设计方案

> 状态：设计稿，待确认后开工。依据：`reports/生物流形的拓扑数据分析.md`（本地，未提交）。

## 一句话

用果蝇头朝向回路的**真实连接组**（hemibrain，可切换 FlyWire）搭一个神经网络，让访客亲手"转动果蝇"，看活动峰（bump）在椭球体上跑；再把 46 个 E-PG 神经元的活动当成 46 维点云，现场算持续同调，得到一根长 H1 条——**解剖上的环，在状态空间里也是一个环**。然后访客可以把回路"弄坏"（删掉 Δ7、打乱权重、只用原始突触数），看这根条怎样消失。

这是目前没人做过的东西：最接近的先例 Duan, Dong & Fiete 2025（bioRxiv）做了同样的计算，但没有代码，也没有交互。

## 一、系统架构

```
 ┌───────────────── 离线（Python，跑在 Modal 上）──────────────────┐
 │ 1 取数据   neuPrint(hemibrain) / FlyWire Codex → 细胞类型、突触数、递质 │
 │ 2 建矩阵   按 PB 小球 / EB 楔形排序，W = 突触数 × 递质符号 × 类型增益   │
 │ 3 拟合     JAX：只训练 ~50 个"细胞类型增益"，损失 = 角速度积分误差     │
 │ 4 验证     Ripser 算 H0/H1/H2；shuffle 零假设；消融实验               │
 │ 5 导出     model_hemibrain.json / model_flywire.json（每个几百 KB）    │
 └──────────────────────────────────────────────────────────────────┘
                 │ 静态 JSON
                 ▼
 ┌──────────────── 浏览器（静态页，放在你的 GCS bucket）──────────────┐
 │ 模拟器   JS 速率模型，~150–450 个神经元，60 fps 实时                  │
 │ 视图     椭球体环 · 连接矩阵 · 发放栅格 · 3D 状态空间 · 条形码          │
 │ 拓扑     Ripser 编译为 WebAssembly，跑在 Web Worker（300–500 点，H1 ~1 s）│
 └──────────────────────────────────────────────────────────────────┘
                 │ 可选：重计算
                 ▼
 ┌──────────────── 在线 API（可选，Modal 或 Cloud Run）────────────────┐
 │ H2、上千个点、Flagser 有向团（连接组图本身的拓扑）、访客自定义消融后重新拟合 │
 └──────────────────────────────────────────────────────────────────┘
```

**为什么这样分：** 真正难、真正花算力的是"拟合增益"（研究结论：原始突触数 × 单一增益做不出稳定 bump，必须拟合少量细胞类型参数），这一步离线做一次就够。访客端只需要跑已经拟合好的小网络和小规模持续同调，浏览器完全扛得住，页面依然是纯静态、可以放在 bucket 上、离线可开。在线 API 只用于"更大、更慢"的可选功能，挂了也不影响主体。

**为什么用 Modal：** 你的环境里已经连好了 Modal，按秒计费，CPU/GPU 都能起，拟合脚本和可选 API 都能放上去，不用另配服务器。拟合规模很小（几百神经元、~50 参数），CPU 就够；需要大规模扫参（比如 FlyWire 和 hemibrain 各种消融组合都重新拟合）时再上 GPU。

## 三、模型

- **形式：** 速率模型 τ·dr/dt = −r + f(W·r + b + I_vel)，f 为 sigmoid 或阈值线性；按 Duan et al. 2025 的配方，W 的每一项 = 突触数 × 递质符号 × 该（前类型→后类型）的增益。
- **可训练参数：** 细胞类型对之间的增益 + 每类偏置 + τ，约 50 个；不改单个突触。这点很重要——页面要能诚实地说"接线来自连接组，我们只调了 50 个旋钮"。
- **输入：** 角速度注入左右两侧 P-EN（或 GLNO），外加可选的"视觉地标"输入（E-PG 局部兴奋）。
- **训练目标：** 随机角速度序列下，从 E-PG 群体向量解码出的角度 = 积分得到的真实角度；加正则让 bump 宽度稳定。
- **两个基线（页面上的对照）：**
  1. 原始突触数 × 单一全局增益（预期：bump 衰减或跳格，没有长 H1）。
  2. Biswas 式 8+8 粗粒化模型（4 个滑块，解析可解，作为最小教学版）。

**第一个里程碑就是风险点：** 先在 Python 里复现出"拟合后稳定 bump + 一根长 H1"。复现不出来，后面的页面就不做这条故事，改做小鼠头朝向（故事 2，真实数据，DANDI 000939，CC-BY）。

## 四、页面设计（topology.html 的姊妹页：`compass.html`）

风格沿用拓扑页：白底墨线，两种强调色（蓝 = H0，红 = H1），英文为主，中文点缀。滚动叙事，左侧固定一块"实验台"，右侧随段落切换说明。

```
┌──────────────────────────────────────────────────────────────────────┐
│ ← All projects                                              罗盘 · Compass │
│ The fly's compass is a ring. Is its activity one too?                     │
├───────────────────────────────┬──────────────────────────────────────┤
│   [实验台，固定]                │ 1 The anatomy is a ring                │
│                                │   E-PG 神经元铺满椭球体的 16 个楔形……     │
│      ◯ 椭球体（16 楔形）        │                                       │
│      ● bump 在环上移动          │ 2 The wiring                           │
│                                │   连接矩阵：P-EN 的投射错开一格……         │
│   ┌──────────┐ ┌────────────┐  │   [悬停一行 = 高亮一个神经元的所有连接]   │
│   │ 连接矩阵  │ │ 发放栅格    │  │                                       │
│   └──────────┘ └────────────┘  │ 3 Turn the fly                         │
│                                │   拖动罗盘 / ← → 键，bump 跟着转          │
│   ┌──────────────────────────┐ │                                       │
│   │ 3D 状态空间（46 维→PCA） │ │ 4 Its activity is a ring, too           │
│   │ 轨迹画出一个圈            │ │   [Compute topology] → 条形码一根长 H1   │
│   └──────────────────────────┘ │                                       │
│   ┌──────────────────────────┐ │ 5 Break it                             │
│   │ 条形码（复用拓扑页组件）  │ │   ☐ 只用原始突触数  ☐ 删掉 Δ7           │
│   └──────────────────────────┘ │   ☐ 打乱权重  ☐ 加噪声 → 长条消失        │
│                                │                                       │
│ 连接组: (hemibrain) FlyWire     │ 6 A mouse has no ring in its brain…     │
│ 罗盘: ◐ 拖动  ▶ 自动转          │   …but its activity is still a ring（后续）│
└───────────────────────────────┴──────────────────────────────────────┘
```

**关键交互**
- **转动果蝇：** 拖动一个罗盘盘面或按方向键 = 角速度输入；bump 在椭球体上跟着走，下方显示"真实朝向 vs 解码朝向"。
- **关灯：** 去掉视觉地标输入，只靠路径积分，看误差慢慢累积（真实果蝇在黑暗中也是这样）。
- **算拓扑：** 记录最近 N 步的 E-PG 状态 → Worker 里 Ripser → 条形码；悬停长 H1 条，3D 视图里高亮对应的环。
- **弄坏它：** 一组开关（原始权重 / 删 Δ7 / 删 ring 神经元 / 打乱块内权重 / 加噪声），每次切换后重新跑、重新算条形码，并排显示"之前 / 之后"两份条形码。
- **换连接组：** hemibrain ⇄ FlyWire，比较两个果蝇大脑接线的差别会不会改变拓扑。
- **零假设：** 一个按钮跑 100 次循环平移 shuffle，在条形码上画出"噪声能达到的最长条"的阈值线——这是统计背景最能发挥的地方。

**每段的英文说明保持很短**，每段 2–3 句，附原论文链接（Seelig & Jayaraman 2015、Kim 2017、Turner-Evans 2017/2020、Hulse 2021、Duan 2025、Chaudhuri 2019、Gardner 2022）。

## 五、技术选型

| 部分 | 选择 | 理由 |
|---|---|---|
| 离线管线 | Python：neuprint-python、pandas、JAX（拟合）、ripser.py、persim | 研究社区标准工具，结果可与论文对照 |
| 计算 | Modal（已连接）| 按秒计费，脚本直接上云，不用管服务器 |
| 前端构建 | Vite（已在 room-src 用过），产出静态文件 | 依然可以放 GCS，可以模块化 |
| 3D 视图 | Three.js（已在流光用过）| 状态空间点云和椭球体 |
| 浏览器拓扑 | Ripser → WebAssembly（参考 live.ripser.org）+ Web Worker | 不卡主线程，H1 几百个点约 1 秒 |
| 可选 API | Modal web endpoint（FastAPI）| H2、Flagser、在线重新拟合 |
| 数据格式 | JSON（权重稀疏化 ≥3 突触，约 2–3 万非零项）| 几百 KB，可缓存 |

拓扑页现有的 JS 持续同调（50 点上限）保留给 2D 教学；新页面换成 WASM Ripser，也可以反过来升级拓扑页。

## 七、风险与诚实声明

- **拟合可能复现不出来**：Duan 等没公开 τ、ℓ、w0 等参数。第 1 阶段就是用来尽早发现这一点。
- **"模拟"不是"记录"**：页面会明确写"这是连接组约束的模拟，不是果蝇的真实神经记录"，真实记录的证据引用 Seelig & Jayaraman、Kim 等人的成像论文。
- **一根长 H1 不等于证明是环**：页面会讲 shuffle 零假设，并提一句 Betti 数的局限（"Doughnut or Mickey Mouse?"）。
- **递质符号**来自预测，有一定错误率；页面注明。
- **许可**：hemibrain 署名即可；FlyWire 仅非商业，需在页面底部写明署名与许可。
- **DeepSeek**：已接好。适合交给它的是机械性批量工作（例如批量生成矩阵统计的描述文本），涉及拟合、拓扑判断和引用核对的部分不交给它。
